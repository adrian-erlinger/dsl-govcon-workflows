# Facilitator Notes: Opportunity Triage

Opportunity Triage is the canonical first workflow and primary training test fixture for this repository. Use it when demonstrating the basic Codex pattern:

**Inspect -> Prompt -> Review -> Question -> Revise**

For first-time users, the recommended live path is [FIRST-RUN-PROMPT.md](../../FIRST-RUN-PROMPT.md): participants use a real public SAM.gov opportunity as the practice target and the repository's synthetic company files as the pretend internal evidence. Coach this as a guided exercise. If a participant has not selected a SAM.gov notice yet, treat that as the next step, not a mistake.

The fully synthetic packet remains useful when the group should avoid web lookup, use a fixed scenario, or compare outputs against the expected-output guide.

## Intended Teaching Tensions

The synthetic case should not produce a clean, overconfident answer. It is designed to make Codex and the participant reason across:

- strong workflow-documentation and job-aid capability overlap;
- no documented customer relationship;
- partial past-performance relevance;
- staffing concerns for simultaneous or on-site delivery;
- an uncommitted training partner;
- missing pricing and evaluation information;
- unclear accessibility acceptance criteria;
- one source conflict about the number of on-site sessions.

## Reasonable Draft Direction

A useful draft will usually land near a cautious **Hold** recommendation unless the participant asks Codex to revise based on additional approved evidence. That is intentional. The training value is in preserving uncertainty, routing questions, and showing what evidence would change the recommendation.

There is no official score or answer key. A score is a discussion aid, not a mathematical rule, and the expected-output guide describes review behaviors, not a final decision.

## Facilitator Checks

Before using the workflow in a session, confirm that:

- `START-HERE.md` points participants to Opportunity Triage first and reassures them that `FIRST-RUN-PROMPT.md` is a valid starting point;
- the source packet index lists every approved synthetic input;
- the prompt names only files that exist in the repository;
- first-run output filenames include the solicitation number so multiple practice runs can sit side by side;
- the expected-output guide asks reviewers to check scores, caveats, missing information, and conflicts;
- the synthetic notice, review criteria, customer context, capability statement, past-performance records, and delivery-capacity data are all present;
- participants understand that no real procurement, client, proposal, pricing, or proprietary data belongs in this repository.

## Suggested Debrief Questions

1. Which conclusion was easiest for Codex to support with source evidence?
2. Which score was most tempting to overstate?
3. Where did a missing fact need to become a reviewer question?
4. How did the source conflict change the staffing or capture discussion?
5. Which issues need BD, capture, technical, pricing, contracts, or leadership review?
6. Which synthetic files resemble documents your organization already maintains?
