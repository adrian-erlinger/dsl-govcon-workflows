# Review and Governance Checklist

Use this before allowing a training workflow to be adapted inside an organization.

## Data Governance

- [ ] Permitted data types are documented.
- [ ] Prohibited sensitive and proprietary data types are documented.
- [ ] An owner can approve input sources.
- [ ] Retention and access rules are understood.

## Workflow Governance

- [ ] The workflow has a named business owner.
- [ ] Each output has a defined purpose and audience.
- [ ] Source traceability is required.
- [ ] Missing information stays visible.
- [ ] Qualified review roles are named.
- [ ] Escalation paths exist for specialist questions.
- [ ] Final decisions remain with authorized people.

## Quality Review

- [ ] Test inputs are synthetic or explicitly approved public information.
- [ ] Expected fields and failure conditions are documented.
- [ ] Reviewers test unsupported facts and conflicting inputs.
- [ ] Users understand that fluent language does not prove accuracy.
- [ ] A process exists to correct, reject, and improve outputs.

## Scope Control

- [ ] No automated submission or outside contact is enabled.
- [ ] No live integration is implied.
- [ ] No application or dependency has been added without separate approval.
- [ ] The workflow does not claim to provide professional advice.
